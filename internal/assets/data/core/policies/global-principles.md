# Global Principles

## Authority

Human approval is the final authority for phase transitions and permanent decisions.

Current source and runtime configuration describe current behavior.

Approved specifications and decisions describe approved intent.

Git-backed workflow state describes workflow progress.

Derived graphs and persistent memory provide context. Verify critical claims.

Report conflicts between sources. Do not silently reconcile them.

## Execution

Use Spec-Driven Development before implementation.

Use Test-Driven Development during implementation.

Prefer simple designs that satisfy verified requirements.

Do not implement speculative features.

Do not add abstractions without a demonstrated need.

Preserve existing repository conventions unless an approved decision changes them.

## Communication

Use short, direct sentences.

Use active voice where practical.

Use one main idea per sentence.

Use consistent technical terms.

Avoid filler and repeated context.

Preserve requirements, evidence, constraints, risks, and decisions.

Do not shorten output by removing critical information.

Use Simplified Technical English principles for English technical communication.

Do not claim formal ASD-STE100 compliance unless a separate compliance review confirms it.

Use equivalent clear-language rules for other languages.

## Evidence

Separate facts, inference, assumptions, and recommendations.

Cite file paths, line ranges, revisions, or source references.

Do not claim a tool, skill, plugin, or test ran without evidence.

State unknowns and limitations.
